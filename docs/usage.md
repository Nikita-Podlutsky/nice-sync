# Nice Sync на Windows и Arch

Windows публикует папку, Arch хранит её зеркало. Сейчас публикация называется `learn`, а общая сеть — `home`.

## Где что лежит

| Что | Где искать |
|---|---|
| Общий конфиг, который нужно редактировать | `C:/configs/network.sync` на Windows |
| Рабочая папка Windows | `C:/Users/pniki/Documents/Учеба` |
| Рабочая папка Arch | `/home/nikita/Documents/Учеба` |
| Состояние Windows-хоста | `C:/configs/nice-sync-state` |
| Состояние Arch | `~/.nice-sync` по умолчанию или каталог, указанный через `--state` |
| Общий конфиг на Arch | `~/.nice-sync/shared.sync`, либо файл из `--publish-config` |
| Установленная программа на Arch | `~/.local/bin/nice-sync` |
| Репозиторий и скрипт сборки | [GitHub](https://github.com/Nikita-Podlutsky/nice-sync) и [scripts/connect-linux.sh](../scripts/connect-linux.sh) |

В репозитории лежат исходники и [примеры](../examples/network.sync). Рабочие файлы Nice Sync передаёт напрямую между узлами в режиме P2P. Правки `shared.sync` с Arch попадают в общий конфиг, если запущенный Windows-узел выдал этому устройству право редактора. Каталоги состояния содержат ключи, регистрацию, архив версий и части незавершённых передач. Используй тот же `--state` при запуске после обновления.

В состоянии Windows файл `applied.json` хранит активный снимок конфига, `access/registry.json` — регистрацию устройств, а `shares/learn/` — историю файлов и архивные объекты. У каждого корня может быть свой архив внутри `shares/learn/roots/`. На Arch файл `joined.json` хранит сведения о членстве, а `sync/learn/` — отметки предыдущего обмена и части загрузок. Твои обычные документы лежат в папках `Учеба` из таблицы.

## Запуск Windows

Если хост уже работает, пользуйся им. Для ручного запуска после остановки текущая сборка находится в `target/windows-browse/nice-sync.exe`:

```powershell
$repo = 'C:/Users/pniki/Documents/Programs/Rust/nice_sync'
$app = "$repo/target/windows-browse/nice-sync.exe"
$state = 'C:/configs/nice-sync-state'
& $app --state $state serve --share-config
```

`Serving 'home'` означает готовность хоста. Строка `Watching` показывает, какой файл он отслеживает. В твоём случае это `C:\configs\network.sync`. Если хост запущен в фоне, его сообщения находятся в свежем файле `serve-*.out.log`, ошибки — в `serve-*.err.log` внутри каталога состояния.

Для нового Windows-хоста или при выборе другого исходного файла сначала проверь конфиг, затем примени его при остановленном `serve`:

```powershell
& $app check C:/configs/network.sync
& $app --state $state plan C:/configs/network.sync --device windows
& $app --state $state apply C:/configs/network.sync --device windows
& $app --state $state serve --share-config
```

## Запуск Arch

Для установки нужны Cargo и компилятор C. Один раз установи программу напрямую из GitHub. Эта же команда подходит для перехода со старой установки.

```bash
cargo install --git https://github.com/Nikita-Podlutsky/nice-sync.git --branch main --locked --force --root "$HOME/.local" nice-sync
~/.local/bin/nice-sync
```

В локальном клоне ту же установку запускает `bash scripts/connect-linux.sh --install-only`. В дальнейшем достаточно выбрать **Обновить из GitHub** в меню или выполнить `~/.local/bin/nice-sync update`. Команда собирает `origin/main` из GitHub и заменяет установленный бинарник после успешной сборки. Действующий процесс продолжит работать до остановки. Ключи, настройки и конфиг хранятся в каталоге состояния.

### Терминальное меню

Стрелки выбирают действие, Enter открывает его, Esc возвращает назад. Если состояние уже создано в `~/.nice-sync`, программа использует его автоматически. Для отдельного профиля передай `nice-sync --state ПУТЬ`. При первом подключении выбери **Подключиться по коду** и вставь приглашение. На Windows код выдаётся командой:

```powershell
& $app --state $state invite --template connect-linux --device linux
```

В **Настройках** доступны источник конфига, интервал, одна публикация или вся сеть, адрес подключения, P2P и вывод маршрута. Для запуска публикации папок также доступны адрес прослушивания, раздача конфига и имя редактора. Настройки сохраняются в `terminal.json` внутри состояния. Чтобы перезапустить процесс с новыми параметрами, выбери **Остановить процесс** и запусти обмен снова.

**Редактировать конфиг** открывает выбранный файл и проверяет его после закрытия редактора. На Linux используется `VISUAL`, затем `EDITOR`, по умолчанию `nano`. Укажи имя или путь к исполняемому файлу редактора. На Windows по умолчанию открывается Блокнот. Общая копия `shared.sync` появится после первого прохода. Для локального файла или применённого конфига выбери **Проверить и применить конфиг**. При конфликте двух правок в каталоге состояния доступна версия `host.sync`.

Синхронизация продолжается, пока открыто меню. Вывод процесса доступен через **Журнал**. Выход из меню останавливает запущенный им процесс. Для скриптов доступны прежние команды `sync`, `serve` и `apply`.

## Что происходит во время обмена

1. Arch получает общий конфиг и берёт из него локальный путь для устройства `linux`.
2. Каждый узел обходит свою папку с учётом исключений. Индекс содержит относительные пути и хеши содержимого. Arch сравнивает индексы и свою отметку о предыдущем обмене.
3. Нужные байты передаются в обе стороны пакетами до 8 МиБ. Один пакет может включать много файлов или части больших. Проверенный файл появляется в рабочей папке. После обрыва сохраняются уже принятые части.
4. Периодический режим ждёт 10 секунд после прохода и запускает следующий. `0 changes` означает, что в этом проходе применять было нечего.

`P2P-only transfer via …` означает, что началась передача по прямому маршруту. Когда прямой UDP-путь недоступен, режим ждёт следующей попытки. Узлы уже могут видеть друг друга через релей на этапе установления связи.

## Посмотреть файлы на Windows без синхронизации

На Arch открой отдельный терминал и выполни `~/.local/bin/nice-sync --state "$HOME/.nice-sync" browse windows:/learn`. В открывшемся просмотре используй `ls`, `cd Имя папки`, `cd ..`, `pwd` и `exit`. Хост запрашивает содержимое только открытого уровня. Вложенные папки внутри `learn` можно открывать, даже если они ещё не скачаны. Для другой папки на Windows можно настроить [корень только для просмотра](language.md#просмотр-без-автоматического-обмена).

## Как изменить настройки

Редактируй `C:/configs/network.sync` на Windows или `~/.nice-sync/shared.sync` на Arch. Изменения с Windows подхватываются примерно за секунду и приходят на Arch при следующем проходе. Правки с Arch сохраняются на Windows в следующем цикле после сохранения файла. Если конфиг содержит ошибку, исправь указанный участок и дождись следующего прохода.

Для настройки редактирования один раз запусти Windows с `serve --share-config --config-editor linux`, и обнови сборки на обоих устройствах. На Arch запусти следующую команду из клона репозитория. Дождись получения `shared.sync` перед первой правкой. Для отдельного файла можно передать `--publish-config ФАЙЛ`.

```bash
git pull --ff-only
bash scripts/connect-linux.sh --p2p-only --show-route
```

Сохраняй сколько угодно правок без перезапуска. Для новой папки добавь блок `share` с путём Windows и правилом для `linux`. Программа создаст оба указанных каталога, если они отсутствуют. Чтобы убрать папку из обмена, удали блок `share` и ссылки на него по имени в разрешениях и приглашениях. Файлы останутся на обоих устройствах. Если удаляешь последний блок `share`, оставь `host windows` внутри `network home`. При смене пути Windows история прежней папки остаётся в отдельном архиве.

| Сообщение или симптом | Что проверить |
|---|---|
| На Arch старый конфиг | Что в строке `Watching` указан нужный файл и клиент работает с `--publish-config` или `--follow-config` |
| `apply a configuration first` | Для общей конфигурации на Arch добавь `--follow-config` к `sync` |
| `opening local folder …` | Доступен ли путь из правила для `linux` и есть ли права на создание папки |
| `no direct P2P path` | Есть ли в выводе успешное `P2P-only transfer via`. До него файловая передача в этом режиме ждёт прямого маршрута |
| Публикация есть, а файла нет | Проверь `ignore` и локальный путь в `shared.sync` |

Разбор строк `network.sync`, всех четырёх режимов, прав и команд терминала находится в [справочнике по языку](language.md).
