# Цель Nice Sync

Nice Sync объединяет личные устройства в равноправную сеть без постоянного хоста. Любой работающий участник может обмениваться настройками и данными с другими доступными участниками. История версий помогает восстановить файлы и сохранить независимые правки. Сеть рассчитана на Windows, Linux, большие бинарные файлы и периодическую работу офлайн.

## Правила папок

Устройства равны по умолчанию. Для каждой общей папки конфиг связывает её имя с локальными путями на участвующих устройствах. Направление обмена, приоритет источника, перезапись, удаления, конфликты и исключения задаются для этой папки. Общие настройки сети могут задавать значения по умолчанию.

| Сценарий | Ожидаемое поведение |
|---|---|
| Архив фотографий | Архивный узел принимает файлы с телефона, сохраняет свои существующие копии и подтверждает сохранение после проверки. Удаление на телефоне оставляет архивную копию. |
| Две папки на ПК и ноутбуке | ПК служит источником для папки проектов, ноутбук служит источником для папки документов. |
| Совместное редактирование | Оба устройства отправляют правки. При независимых изменениях сохраняются обе версии. Правило папки определяет, распространяются ли удаления. |
| Проекты и модели | Ноутбук получает код без GGUF. Общее исключение исключает каталоги .venv. Смена фильтра сохраняет уже скачанные файлы. |
| Удалённый просмотр | CLI перечисляет непосредственные дочерние записи удалённой папки. Права определяют, можно ли читать файлы и версии вручную. |

## Общий конфиг

`network.sync` представляет одну логическую конфигурацию с локальной копией на каждом устройстве. Каждый зарегистрированный участник может изменить любые правила, включая обмен между двумя другими устройствами. Приложение всегда проверяет и обменивается версиями конфига каждые несколько секунд, в том числе между устройствами без общих папок. После возвращения офлайн-узла его правки участвуют в следующем обмене.

Сохранённая корректная правка становится новой версией с известным предком. Получение старой копии сохраняет новую версию. При независимых правках сохраняются обе редакции до объединения. Некорректный текст остаётся доступен для исправления, а обмен использует последнюю проверенную конфигурацию.

## Индекс и данные

Каждый узел хранит в метаданных приложения единый логический индекс. Он связывает папку и путь с версиями, их происхождением и хешами и позволяет вычислить направления и очередь передач из правил. Время помогает читать историю. Порядок версий и конфликты определяются по связям между версиями.

Узлы сравнивают индексы и группируют нужные файлы и части больших файлов в пакеты. Текущий размер пакета до 8 МиБ служит отправной точкой. После обрыва передача продолжается с подтверждённого состояния, конечная версия появляется после проверки содержимого. Оптимизация параллельности и загрузки канала следует за проверкой корректности.

## Вход и обнаружение

Новое устройство вводит один код и связывается с любым доступным участником. После регистрации оно получает общий конфиг и каталог идентификаторов устройств с данными для установления связи. Каталог распространяется по всей сети, включая пары устройств без правил обмена папками. Права на данные определяются при обращении к папке. В качестве первого способа входа подходит приглашение от одного доступного узла. Единый код сети или мнемоника для поиска доступных участников остаются вариантом развития. Закрытые ключи устройств хранятся локально.

## Текущая реализация

Сегодня CLI использует один узел `serve` для публикаций и распространения конфига. Клиенты сравнивают индексы с этим узлом и обмениваются пакетами до 8 МиБ. Зарегистрированный редактор может отправить правку общего файла в периодическом цикле. Действующие команды и синтаксис описаны в [руководстве](usage.md) и [справочнике](language.md). Переход к равноправной сети описан в [этапах](roadmap.md).
