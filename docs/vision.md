# Цель Nice Sync

Пользователь управляет сетью своих устройств и задаёт разные правила хранения одной папки на разных узлах. От Git берём историю версий, происхождение изменений и обнаружение конфликтов. Обмен рассчитан в том числе на большие бинарные файлы и работу устройств офлайн.

| Сценарий | Ожидаемое поведение |
|---|---|
| Фото с телефона | Сервер подтверждает архивирование после проверки и сохранения файла. Удаление с телефона сохраняет архивную копию. Новое содержимое по тому же пути образует версию. |
| Документы на сервере и ноутбуке | Правки обмениваются в обе стороны. При независимых правках обе версии остаются доступны. Распространение удаления задано политикой. |
| Проекты и модели | ПК отправляет проект с весами на сервер. Ноутбук автоматически получает код без GGUF. Каталоги .venv исключаются во всей сети. |
| Подключение ноутбука | Сервер или уполномоченный телефон выпускает одноразовый код. Ноутбук вводит код и подключается автоматически. Политика приглашения задаёт доступ к выбранным или всем опубликованным папкам. |
| Удалённый просмотр | Из CLI можно открыть опубликованный корень и пройти по вложенным папкам без синхронизации. Каждый запрос читает один уровень. С отдельным правом можно скачать файл или выбранную версию. |

## Правила хранения

- Правила ignore действуют на состав передачи. Применение нового правила не удаляет уже скачанные файлы и не меняет права на ручное скачивание.
- При полном обходе хост пропускает исключения уровня сети и публикации. Ручной запрос по точному пути может проиндексировать отдельный исключённый файл.
- Журнал связывает версию с папкой, путём, устройством, исходной версией и хешем. Время полезно для отображения истории. Конфликт определяется по происхождению версий.
- При обрыве незавершённый файл остаётся во временном состоянии. Конечный файл становится доступен после проверки целостности.
- Границы опубликованных корней и права проверяются на сервере для каждой операции.
- История публикации привязана к её корню на хосте. Замена корня открывает отдельный архив для новой папки.
- Узлы создают отсутствующие папки по путям из конфига. Если целиком пропал корень обмена, программа восстанавливает его из доступной истории или с другого узла. Удаление блока публикации прекращает обмен и оставляет файлы на диске.
- Хост открывает соединения до обхода файлов. Полный обход нужен для снимка синхронизации. Просмотр каталога перечисляет только непосредственные дочерние записи.
- Клиент загружает несколько разных файлов одновременно. Установка файлов и запись синхронизированных версий происходят после проверки содержимого.
- Обновлённые узлы сначала сравнивают индексы. Затем они передают только нужные данные в обоих направлениях пакетами до 8 МиБ. Пакет может содержать много файлов и части крупных файлов.

## Платформы и подключение

Хост может публиковать общий снимок применённого конфига и перечитывать исходный файл во время работы. Зарегистрированные устройства получают обновлённый снимок на следующем проходе синхронизации. При ошибке в файле хост продолжает работать с последним проверенным снимком.

Клиент может перечитывать свой локальный файл перед каждым проходом. Ручные изменения клиентской копии общего конфига сохраняются отдельно от новой версии, полученной с хоста.

Устройство с правом редактирования общего конфига может отправить новый снимок с добавленными, изменёнными или удалёнными публикациями. Хост сверяет исходную версию, проверяет кандидат и записывает его в свой исходный файл. Когда обе стороны изменили файл независимо, устройство сохраняет обе версии для объединения.

Первая версия — программа на Rust с терминальным интерфейсом для Windows и Linux. Подключение по действительному коду автоматически привязывает ключ нового устройства к выданным правам. Сетевой обмен использует доступные приложению маршруты при работающем VPN и действующих настройках системы. Мобильный клиент запланирован после настольной версии.

Клиент может показать выбранный транспортный маршрут и использовать явно указанный UDP-адрес с проверкой зарегистрированного ключа хоста.
Режим P2P-only использует релей для поиска пути и открывает отдельное соединение для прямой передачи файлов.
